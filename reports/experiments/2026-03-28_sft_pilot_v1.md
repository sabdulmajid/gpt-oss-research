# Summary

This run converted the repository from a planning/bootstrap state into a working pilot loop:

- materialize a real SFT slice from public sources
- train a short `gpt-oss-20b` LoRA adapter locally
- measure base versus SFT adapter on the internal eval seed

The main useful outcome is that the repo now has a working end-to-end SFT path with saved artifacts and a measurable before/after result.

# Evaluation Outputs

Internal `ML Research Eval` seed result:

- base `gpt-oss-20b`: `1/4` pass@1
- SFT pilot adapter: `3/4` pass@1

The pilot adapter solved:

- `data_collator_pad_labels`
- `training_detach_metrics`
- `transformer_masked_mean_pool`

The remaining miss was:

- `autograd_clip_grad`

Public benchmark holdouts were not run in this pilot. That work still needs a clean harness and should be done before any broad performance claim.

# GRPO Status

The GRPO path is no longer theoretical:

- the repo materialized a real verifiable GRPO slice
- the trainer was brought to the point of executing live generation/reward steps on GPU
- one pilot step completed at roughly 268s/step before the long run was intentionally stopped

The remaining blocker is not dataset wiring. It is practical runtime and compatibility work for a longer GRPO pilot on this hardware/software stack.

# Claims

Claims supported by stored outputs:

- the repo can materialize a real SFT slice and a real verifiable GRPO slice
- the repo can train a local `gpt-oss-20b` LoRA adapter on the current hardware
- the short SFT pilot improved the current 4-task internal eval seed from `1/4` to `3/4`

Claims not supported by this run:

- that the current SFT mix is optimal
- that the model is broadly better
- that the pilot result transfers to public holdouts
- that GRPO has improved results on this setup yet
